2. Installer sur Windows, macOS et Linux

Windows 10/11 (PowerShell)

Moteur Installation Vérification
SQLite winget install --id SQLite.SQLite -e sqlite3 --version
MySQL MSI officiel MySQL 8.4, puis MySQL Configurator mysql --version
PostgreSQL Installateur officiel PostgreSQL psql --version

winget search --id SQLite.SQLite

L'installation MySQL exige une configuration du serveur et de l'authentification ; le serveur ne démarre pas tant que cette étape n'est pas terminée. PostgreSQL propose souvent un rôle administrateur initial postgres. Si les programmes sont introuvables, rouvrir PowerShell et vérifier le PATH ainsi que le répertoire bin de l'installation.

macOS (Homebrew)

Bash / Zsh
brew install sqlite
brew install mysql@8.4
brew install postgresql@18
brew services start mysql@8.4
brew services start postgresql@18
sqlite3 --version
"$(brew --prefix mysql@8.4)/bin/mysql" --version
"$(brew --prefix postgresql@18)/bin/psql" --version

Les formules versionnées peuvent ne pas être liées automatiquement au PATH. Pour ce terminal seulement :

Bash / Zsh
export PATH="$(brew --prefix mysql@8.4)/bin:$(brew --prefix postgresql@18)/bin:$PATH"
command -v sqlite3
command -v mysql
command -v psql

Sur les anciens macOS, vérifier l'existence de paquets précompilés avant une installation Homebrew : des compilations ou mises à jour importantes peuvent être nécessaires. macOS fournit parfois déjà une version de SQLite.

Linux : Debian / Ubuntu (APT)

Bash / Zsh
sudo apt update
sudo apt install sqlite3 mysql-server postgresql postgresql-contrib
sqlite3 --version

psql --version
sudo systemctl status mysql
sudo systemctl status postgresql

Les versions proviennent des dépôts de la distribution. Si une version précise de PostgreSQL est indispensable, consulter le dépôt PostgreSQL officiel. Sur Ubuntu, PostgreSQL utilise souvent l'authentification locale peer et MySQL root peut utiliser l'authentification par socket.

Linux : Fedora (DNF)

Bash / Zsh
sudo dnf install sqlite mysql-server postgresql postgresql-server
sudo postgresql-setup --initdb --unit postgresql
sudo systemctl enable --now mysqld
sudo systemctl enable --now postgresql

psql --version

Initialisation Fedora : postgresql-setup --initdb est destinée uniquement à un nouveau cluster non initialisé. Les noms de services et les paquets changent selon les distributions et les dépôts.

4. Connexions, bases et navigation

SQLite : ouvrir, créer et basculer entre fichiers

Dans le terminal :

Bash / Zsh
sqlite3 ma_base.db
sqlite3 -readonly ma_base.db
sqlite3 :memory:

Dans le client SQLite :

Client interactif
.help
.open ma_base.db
.open --ifexists ma_base.db
.open --readonly ma_base.db
.databases
.tables
.schema
.schema users
.indexes users
.quit

sqlite3 ma_base.db crée le fichier s'il n'existe pas et si le dossier est accessible. .databases affiche les bases de la connexion (main, temp et fichiers attachés), pas tous les fichiers du disque. Pour voir les fichiers .db du répertoire, employer ls *.db (macOS/Linux) ou Get-ChildItem *.db (PowerShell).

SQL
ATTACH DATABASE 'archives.db' AS archives;
SELECT * FROM archives.users;
DETACH DATABASE archives;
PRAGMA database_list;

MySQL : connexion locale et distante

Dans le terminal :

Bash / Zsh
mysql -u root -p
mysql -u alice -p -D ma_base
mysql -h 127.0.0.1 -P 3306 -u alice -p ma_base
mysql -h db.exemple.fr -P 3306 -u alice -p --ssl-mode=REQUIRED ma_base
mysql -u alice -p -e "SHOW DATABASES;"

Sur Ubuntu, si root est configuré pour une authentification par socket :

Bash / Zsh
sudo mysql

Dans le client MySQL :

SQL
SHOW DATABASES;
SELECT DATABASE();
USE ma_base;
SHOW TABLES;
SHOW FULL TABLES;
SELECT USER(), CURRENT_USER();
SELECT VERSION();
Client interactif
status
help
exit

Pour changer d'utilisateur, quitter puis se reconnecter avec mysql -u autre -p -D ma_base. USE ne change que de base. USER() reflète le compte demandé pour la connexion, CURRENT_USER() le compte utilisé pour contrôler les privilèges.

PostgreSQL : connexion locale et distante

Dans le terminal :

Bash / Zsh
psql -U alice -d ma_base
psql -h 127.0.0.1 -p 5432 -U alice -d ma_base
psql "host=db.exemple.fr port=5432 dbname=ma_base user=alice sslmode=require"
psql -U alice -d ma_base -c "SELECT current_user, current_database();"
psql -U alice -d ma_base -v ON_ERROR_STOP=1 -f setup.sql

Sur Debian / Ubuntu :

Bash / Zsh
sudo -u postgres psql -d postgres

Sur macOS, avec un cluster Homebrew initialisé sous votre compte utilisateur :

Bash / Zsh
psql -U "$(whoami)" -d postgres
psql -U "$(whoami)" -d postgres -c '\du'

Important : le rôle postgres n'est pas systématiquement créé lors de l'initialisation d'un cluster macOS. L'administrateur initial peut porter le nom de l'utilisateur du système. Pour les accès distants sensibles, --ssl-mode=REQUIRED (MySQL) et sslmode=require (PostgreSQL) chiffrent le trafic, mais ne garantissent pas à eux seuls la vérification de l'identité du serveur : configurer la validation du certificat (VERIFY_IDENTITY ou verify-full) et l'autorité de certification adaptée.

Dans psql :

Client interactif
\conninfo
\l
\c ma_base
\c ma_base alice
\c postgres
\du
\dn
\dt
\dt *.*
\d users
\d+ users
\q

\c ma_base alice se reconnecte avec l'identité alice. SET ROLE autre_role; change seulement le rôle SQL actif, sous réserve des autorisations de rôle ; RESET ROLE; le restaure.

* Lire mysql.user nécessite les privilèges nécessaires. Sans accès, SHOW GRANTS; montre les droits de votre session. ** En MySQL, DATABASE et SCHEMA sont généralement synonymes ; PostgreSQL distingue nettement base et schéma.

SQLite :

SQL
SELECT name, type FROM sqlite_schema
WHERE type IN ('table', 'view', 'index')
ORDER BY type, name;

MySQL :

SQL
SELECT table_schema, table_name, table_type
FROM information_schema.tables
WHERE table_schema = 'ma_base'
ORDER BY table_name;

PostgreSQL :

SQL
SELECT schemaname, tablename
FROM pg_catalog.pg_tables
WHERE schemaname NOT IN ('pg_catalog', 'information_schema')
ORDER BY schemaname, tablename;

6. Créer, renommer et supprimer des bases

SQLite

Ouvrir sqlite3 nouvelle.db suffit pour créer une base locale. Pour accéder simultanément à un autre fichier :

SQL
ATTACH DATABASE 'autre.db' AS autre;
SELECT * FROM autre.users;
DETACH DATABASE autre;

SQLite ne possède pas CREATE DATABASE, SHOW DATABASES, DROP DATABASE ou USE au sens des serveurs SQL. Pour supprimer une base SQLite, fermer toutes les connexions puis supprimer le fichier par l'explorateur de fichiers. En mode WAL, ne pas supprimer arbitrairement les fichiers auxiliaires -wal et -shm d'une base ouverte.

MySQL

SQL
CREATE DATABASE ma_base CHARACTER SET utf8mb4;
CREATE DATABASE IF NOT EXISTS ma_base CHARACTER SET utf8mb4;
SHOW CREATE DATABASE ma_base;
USE ma_base;
ALTER DATABASE ma_base CHARACTER SET utf8mb4;
DROP DATABASE ma_base;
DROP DATABASE IF EXISTS ma_base;

MySQL ne fournit pas de commande directe standard RENAME DATABASE. Prévoir une migration contrôlée (création de la nouvelle base, transfert, vérification, suppression de l'ancienne).

PostgreSQL

SQL
CREATE DATABASE ma_base;
CREATE DATABASE ma_base OWNER alice;
ALTER DATABASE ma_base OWNER TO alice;
ALTER DATABASE ma_base RENAME TO autre_base;
DROP DATABASE ma_base;
DROP DATABASE IF EXISTS ma_base;

Les outils système associés :

Bash / Zsh
createdb -U alice ma_base
createdb -U alice -O alice ma_base
dropdb -U alice ma_base

Pour supprimer une base, se connecter à une autre base (par exemple postgres) et s'assurer qu'aucune autre session ne l'utilise. CREATE DATABASE et DROP DATABASE ne s'exécutent pas dans une transaction SQL explicite.

Schémas PostgreSQL

SQL
CREATE SCHEMA IF NOT EXISTS cours;
SET search_path TO cours, public;
SHOW search_path;
SELECT current_schema();
DROP SCHEMA cours;
DROP SCHEMA cours CASCADE;

DROP SCHEMA ... CASCADE supprime aussi les objets dépendants ; examiner les objets et faire une sauvegarde avant de l'exécuter.

7. Utilisateurs, rôles, mots de passe et droits

SQLite : pas d'utilisateurs SQL

SQLite ne possède ni CREATE USER, ni CREATE ROLE, ni GRANT natifs. L'accès dépend principalement des permissions sur le fichier et son dossier. Une table users dans une application représente des comptes métiers, pas des comptes d'administration du moteur.

MySQL : utilisateurs et droits

SQL
SELECT user, host FROM mysql.user ORDER BY user, host;
SELECT USER(), CURRENT_USER();
SHOW GRANTS;
SHOW GRANTS FOR 'alice'@'localhost';
SHOW CREATE USER 'alice'@'localhost';
CREATE USER 'alice'@'localhost' IDENTIFIED BY 'mot_de_passe_fort';
ALTER USER 'alice'@'localhost' IDENTIFIED BY 'nouveau_mot_de_passe_fort';
RENAME USER 'alice'@'localhost' TO 'alice2'@'localhost';
DROP USER 'alice2'@'localhost';
GRANT SELECT, INSERT, UPDATE ON ma_base.* TO 'alice'@'localhost';
REVOKE UPDATE ON ma_base.* FROM 'alice'@'localhost';
GRANT ALL PRIVILEGES ON ma_base.* TO 'alice'@'localhost';
SHOW GRANTS FOR 'alice'@'localhost';

CREATE USER ne donne pas de privilèges métier par défaut. Ne pas privilégier 'alice'@'%' ou GRANT ALL ON *.* sans besoin explicite. FLUSH PRIVILEGES n'est pas nécessaire après des commandes normales CREATE USER, GRANT et REVOKE.

Rôles MySQL et activation :

SQL
CREATE ROLE 'lecture_seule'@'%';
GRANT SELECT ON ma_base.* TO 'lecture_seule'@'%';
GRANT 'lecture_seule'@'%' TO 'alice'@'localhost';
SET DEFAULT ROLE 'lecture_seule'@'%' TO 'alice'@'localhost';
SHOW GRANTS FOR 'alice'@'localhost';
SELECT CURRENT_ROLE();
SET ROLE 'lecture_seule'@'%';
SET ROLE DEFAULT;
REVOKE 'lecture_seule'@'%' FROM 'alice'@'localhost';
DROP ROLE 'lecture_seule'@'%';

Le @'%' du rôle précise sa forme de nom dans l'exemple ; cela ne doit pas être confondu avec l'autorisation réseau d'un compte de connexion 'alice'@'%'. SET ROLE active un rôle accordé, mais ne change pas le compte connecté.

PostgreSQL : rôles, groupes et propriétaires

SQL
SELECT rolname, rolcanlogin, rolsuper, rolcreatedb, rolcreaterole
FROM pg_roles ORDER BY rolname;
SELECT current_user, session_user;
CREATE ROLE alice LOGIN;
CREATE USER carol;
ALTER USER carol CREATEDB;
DROP USER carol;
CREATE ROLE bob LOGIN CREATEDB;
CREATE ROLE lecture_seule NOLOGIN;
ALTER ROLE alice WITH LOGIN;
ALTER ROLE alice WITH PASSWORD 'mot_de_passe_fort';
ALTER ROLE alice WITH NOCREATEDB;
DROP ROLE bob;
GRANT lecture_seule TO alice;
REVOKE lecture_seule FROM alice;
SET ROLE lecture_seule;
RESET ROLE;

Dans PostgreSQL, CREATE USER et ALTER USER sont des variantes pratiques de CREATE ROLE ... LOGIN et ALTER ROLE. Pour définir un mot de passe sans l'inscrire dans une instruction SQL et dans l'historique :

Client interactif
\password alice
\du
\du+

Accorder une lecture des tables existantes dans une base, une fois connecté à cette base avec les droits nécessaires :

SQL
GRANT CONNECT ON DATABASE ma_base TO alice;
GRANT USAGE ON SCHEMA public TO alice;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO alice;
REVOKE SELECT ON ALL TABLES IN SCHEMA public FROM alice;

Pour les futures tables, en tant que leur propriétaire ou sous un rôle autorisé :

SQL
ALTER DEFAULT PRIVILEGES FOR ROLE proprietaire IN SCHEMA public
GRANT SELECT ON TABLES TO alice;

Cette dernière instruction s'applique aux tables futures créées par proprietaire, pas rétroactivement et pas automatiquement à tous les créateurs possibles. Le simple GRANT CONNECT n'autorise pas la lecture des tables. Des accès peuvent exister via les privilèges PUBLIC ou l'appartenance à d'autres rôles.

SQL
ALTER TABLE public.users OWNER TO alice;
ALTER DATABASE ma_base OWNER TO alice;

Dans psql, consulter les droits avec \dp (ou \z) et la liste des rôles avec \du.

8. Tables, colonnes, index, vues et contraintes

Exemple de création d'une table par moteur

SQLite :

SQL
CREATE TABLE IF NOT EXISTS users (
 id INTEGER PRIMARY KEY,
 name TEXT NOT NULL,
 email TEXT UNIQUE,
 created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

MySQL :

SQL
CREATE TABLE IF NOT EXISTS users (
 id BIGINT AUTO_INCREMENT PRIMARY KEY,
 name VARCHAR(120) NOT NULL,
 email VARCHAR(255) UNIQUE,
 created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

PostgreSQL :

SQL
CREATE TABLE IF NOT EXISTS public.users (
 id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
 name VARCHAR(120) NOT NULL,
 email VARCHAR(255) UNIQUE,
 created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

L'identifiant auto-généré et certains types ne sont pas interchangeables entre les trois moteurs. PostgreSQL propose encore SERIAL, mais IDENTITY est une option moderne pour les nouveaux schémas.

Index et vues, exemples indépendants :

SQL
CREATE INDEX idx_users_name ON users(name);
CREATE UNIQUE INDEX idx_users_email ON users(email);
CREATE VIEW vue_users AS SELECT id, name FROM users;
DROP VIEW IF EXISTS vue_users;

Pour supprimer un index :

SQL
DROP INDEX idx_users_name;

L'exemple précédent s'applique à SQLite et PostgreSQL. En MySQL, la syntaxe est :

SQL
DROP INDEX idx_users_name ON users;

Inspection :

SQL
PRAGMA table_info(users);
PRAGMA foreign_key_list(users);
PRAGMA index_list(users);
SQL
DESCRIBE users;
SHOW CREATE TABLE users;
SHOW INDEX FROM users;
Client interactif
\d users
\d+ users
\di
\dv
\df

Attention à TRUNCATE. SQLite ne propose pas TRUNCATE. MySQL effectue généralement un commit implicite pour cette opération DDL, tandis que PostgreSQL permet de l'inclure dans une transaction. Les clés étrangères peuvent empêcher certaines suppressions.

9. SQL quotidien : lire, ajouter, modifier et supprimer

Les requêtes suivantes sont compatibles avec les trois moteurs si la table et les colonnes existent :

SQL
INSERT INTO users (name, email) VALUES ('Ada', 'ada@example.org');
SELECT * FROM users;
SELECT id, name FROM users WHERE id = 1;
SELECT * FROM users ORDER BY id DESC LIMIT 10;
SELECT COUNT(*) FROM users;
SELECT name, COUNT(*) AS total FROM users GROUP BY name;
SELECT name FROM users WHERE email IS NOT NULL;
UPDATE users SET name = 'Ada Lovelace' WHERE id = 1;
DELETE FROM users WHERE id = 1;

Sécurité. UPDATE ou DELETE sans WHERE s'applique à toutes les lignes. Vérifier la sélection avant de modifier des données sensibles. Les transactions suivantes constituent des exemples indépendants :

SQL
BEGIN;
UPDATE users SET name = 'Test' WHERE id = 1;
ROLLBACK;
BEGIN;
UPDATE users SET name = 'Validé' WHERE id = 1;
COMMIT;

Pour MySQL, privilégier le moteur transactionnel InnoDB ; de nombreuses instructions DDL effectuent un commit implicite. Pour SQLite, activer explicitement les clés étrangères si elles doivent être vérifiées dans cette connexion :

SQL
PRAGMA foreign_keys = ON;
PRAGMA foreign_keys;
Besoin SQLite MySQL PostgreSQL
Limiter 10 lignes LIMIT 10 LIMIT 10 LIMIT 10
Concaténer `'a' 'b'`
Date courante CURRENT_TIMESTAMP CURRENT_TIMESTAMP CURRENT_TIMESTAMP
Insertion, ignorer doublon INSERT OR IGNORE ... INSERT IGNORE ... INSERT ... ON CONFLICT DO NOTHING
Mise à jour si conflit INSERT ... ON CONFLICT(...) DO UPDATE ... INSERT ... ON DUPLICATE KEY UPDATE ... INSERT ... ON CONFLICT(...) DO UPDATE ...
Plan de requête EXPLAIN QUERY PLAN SELECT ...; EXPLAIN SELECT ...; EXPLAIN SELECT ...;
Plan avec exécution Selon les outils EXPLAIN ANALYZE SELECT ...; EXPLAIN ANALYZE SELECT ...;

EXPLAIN ANALYZE exécute réellement la requête dans MySQL et PostgreSQL. Les variantes UPSERT doivent se fonder sur des clés ou contraintes uniques appropriées. Pour les jointures, agrégations, WHERE, ORDER BY, GROUP BY, HAVING et JOIN, la syntaxe SQL de base est largement commune aux trois systèmes.

10. Exécuter des scripts SQL, CSV et exports

Moteur macOS / Linux (Bash, Zsh) Windows PowerShell

Les exemples PowerShell évitent <, dont la prise en charge diffère de Bash, notamment dans Windows PowerShell 5.1. Selon les chemins utilisés, vérifier les guillemets et privilégier les chemins absolus en présence d'espaces.

LOAD DATA LOCAL INFILE '/chemin/users.csv'
INTO TABLE users
FIELDS TERMINATED BY ',' ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 LINES;

PostgreSQL, dans le client psql :

Client interactif
\copy users(name,email) FROM 'users.csv' WITH (FORMAT csv, HEADER true)
\copy users TO 'export_users.csv' WITH (FORMAT csv, HEADER true)

\copy lit et écrit côté client. COPY SQL lit et écrit côté serveur, avec des contraintes de permissions différentes. Pour les fichiers sous Windows, on peut employer C:/data/users.csv. Vérifier séparateurs, en-têtes, fins de ligne, jeu de caractères et types de colonnes.

11. Sauvegarder, restaurer et contrôler l'intégrité

SQLite : sauvegarde native et dump SQL

Dans le client SQLite :

Client interactif
.backup sauvegarde.db
.restore sauvegarde.db
.output export.sql
.dump
.output stdout

Dans un terminal macOS ou Linux :

Bash / Zsh
sqlite3 ma_base.db ".backup sauvegarde.db"
sqlite3 ma_base.db ".dump" > sauvegarde.sql
sqlite3 nouvelle_base.db < sauvegarde.sql
sqlite3 ma_base.db "PRAGMA integrity_check;"

Pour PowerShell, exécuter plutôt .backup, .restore ou .read dans le client, afin d'éviter les problèmes de redirection/encodage des anciennes versions. .backup s'appuie sur le mécanisme de sauvegarde SQLite et convient mieux qu'une simple copie à chaud du fichier actif.

MySQL : mysqldump et import

macOS / Linux :

Bash / Zsh
mysqldump -u alice -p --single-transaction --quick --routines --events --triggers ma_base > sauvegarde.sql
mysql -u alice -p -D ma_base < sauvegarde.sql
mysqldump -u root -p --single-transaction --databases ma_base > sauvegarde_avec_base.sql

Windows PowerShell :

PowerShell
mysqldump -u alice -p --single-transaction --quick --routines --events --triggers --result-file=sauvegarde.sql ma_base
mysql -u alice -p -D ma_base -e "source C:/backups/sauvegarde.sql"

L'option --result-file évite notamment certaines difficultés d'encodage liées à la redirection PowerShell. L'option --databases ajoute les instructions de création/sélection de la base. --single-transaction garantit une capture cohérente pour InnoDB dans les conditions documentées, sans DDL concurrent modifiant les objets sauvegardés.

PostgreSQL : pg_dump, pg_restore et pg_dumpall

Bash / Zsh
pg_dump -U alice -d ma_base -F c -f sauvegarde.dump
createdb -U alice restauration
pg_restore -U alice -d restauration --no-owner --exit-on-error sauvegarde.dump
pg_dump -U alice -d ma_base -f sauvegarde.sql
psql -U alice -d restauration -v ON_ERROR_STOP=1 -f sauvegarde.sql

Les archives -F c se restaurent avec pg_restore; les dumps SQL texte, avec psql. La base restauration doit exister pour ces exemples.

Rôles et objets globaux, absents d'une sauvegarde individuelle pg_dump :

Bash / Zsh
pg_dumpall -U alice --globals-only -f roles_et_globals.sql

Cette commande nécessite des droits suffisants pour extraire les données globales, particulièrement celles liées aux rôles. alice n'est qu'un exemple : utiliser un véritable compte administrateur approprié. Selon l'installation, ce compte peut être postgres ou porter un autre nom.

Bonnes pratiques : tester la restauration dans une base de test, vérifier les fichiers et les codes de sortie, éviter les mots de passe visibles dans les scripts, chiffrer/protéger les archives et contrôler la compatibilité des versions, extensions et rôles avant une migration.

12. Administration, diagnostics et performances

SQLite

SQL
PRAGMA foreign_keys;
PRAGMA integrity_check;
PRAGMA quick_check;
PRAGMA journal_mode;
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
PRAGMA database_list;
VACUUM;
ANALYZE;
Client interactif
.timer on
.eqp on
.mode box
.headers on

WAL modifie la journalisation et implique potentiellement des fichiers auxiliaires. VACUUM peut exiger un espace disque supplémentaire et interrompre des opérations selon le contexte.

MySQL

SQL
SHOW PROCESSLIST;
SHOW FULL PROCESSLIST;
SHOW VARIABLES LIKE 'max_connections';
SHOW VARIABLES LIKE 'port';
SHOW GLOBAL STATUS LIKE 'Threads_connected';
SHOW ENGINE INNODB STATUS;
EXPLAIN SELECT * FROM users WHERE id = 1;
ANALYZE TABLE users;
OPTIMIZE TABLE users;
Bash / Zsh
mysqladmin -u root -p status
mysqladmin -u root -p ping

Pour arrêter une connexion précisément identifiée avec les privilèges nécessaires :

SQL
KILL CONNECTION 123;

OPTIMIZE TABLE peut être coûteux et provoquer une reconstruction : évaluer l'effet en production.

PostgreSQL

SQL
SELECT pg_backend_pid();
SHOW port;
SHOW data_directory;
SHOW search_path;
SELECT pid, usename, datname, state, query
FROM pg_stat_activity;
EXPLAIN SELECT * FROM users WHERE id = 1;
EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM users WHERE id = 1;
ANALYZE users;
VACUUM (ANALYZE) users;
Client interactif
\timing on
\x auto
\pset pager off
\watch 5

\watch 5 répète la dernière requête environ toutes les cinq secondes : arrêter avec Ctrl+C. Selon les droits, annuler une requête ou terminer une connexion après vérification du PID :

SQL
SELECT pg_cancel_backend(12345);
SELECT pg_terminate_backend(12345);

pg_cancel_backend tente d'annuler la requête en cours ; pg_terminate_backend termine la connexion. Ne pas confondre VACUUM avec VACUUM FULL, beaucoup plus intrusif.

13. Dépannage : messages fréquents

Problème Cause plausible Diagnostic ou solution
FATAL: role "postgres" does not exist Cluster PostgreSQL initialisé sous un autre rôle (cas possible avec Homebrew) Sur macOS : psql -U "$(whoami)" -d postgres -c '\du'. Ne pas créer un autre superutilisateur sans nécessité.
FATAL: database "alice" does not exist psql -U alice cherche par défaut la base alice Préciser -d postgres ou -d ma_base.
Peer authentication failed Méthode d'authentification PostgreSQL liée au compte OS Sur Ubuntu/Debian : sudo -u postgres psql -d postgres, si le rôle existe.
connection refused Serveur arrêté, mauvais port/hôte ou blocage réseau Vérifier service, pg_isready, mysqladmin ping, hôte et port.
Access denied for user 'root'@'localhost' (MySQL) Mot de passe ou méthode d'authentification non conforme Sur Ubuntu, essayer sudo mysql si l'authentification par socket est configurée.
Unknown database 'ma_base' (MySQL) Base inexistante ou mauvais serveur Se connecter sans -D, lancer SHOW DATABASES;.
No database selected (MySQL) Aucune base active USE ma_base; ou connexion avec -D ma_base.
relation "users" does not exist (PostgreSQL) Mauvaise base ou mauvais schéma \conninfo, \dt *.*, SHOW search_path;, SELECT * FROM public.users;.
database is locked (SQLite) Transaction concurrente en écriture Identifier la connexion, finir sa transaction, essayer PRAGMA busy_timeout=5000;.
unable to open database file (SQLite) Chemin erroné, droits insuffisants ou dossier absent Vérifier le dossier, les permissions, le chemin absolu et .open --ifexists.
Commande introuvable Outil absent du PATH Vérifier installation et dossier bin, puis rouvrir le terminal.
permission denied for table Privilèges manquants PostgreSQL : \dp, GRANT USAGE sur schéma et droits sur table ; MySQL : SHOW GRANTS;.
