## Pourquoi décrire la structure avant les données ?

Une table est un **contrat** : elle fixe les colonnes, leurs types et les règles que toute ligne devra respecter. `CREATE TABLE` écrit ce contrat. Les données viendront ensuite (chapitre 5).

## Anatomie d’un CREATE TABLE

Voici la table `categories`, la plus simple. Elle est volontairement présentée sur les trois moteurs.

:::tabs
```sql pg
CREATE TABLE categories (
    category_id   INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    category_name VARCHAR(60) NOT NULL UNIQUE,
    description   VARCHAR(200)
);
```
```sql mysql
CREATE TABLE categories (
    category_id   INT AUTO_INCREMENT PRIMARY KEY,
    category_name VARCHAR(60) NOT NULL UNIQUE,
    description   VARCHAR(200)
) ENGINE=InnoDB;
```
```sql sqlite
CREATE TABLE categories (
    category_id   INTEGER PRIMARY KEY AUTOINCREMENT,
    category_name VARCHAR(60) NOT NULL UNIQUE,
    description   VARCHAR(200)
);
```
:::

Ligne par ligne :

- `CREATE TABLE categories (…)` : crée une table nommée `categories`. Chaque ligne entre parenthèses, séparée par une virgule, est une **colonne** (ou une contrainte).
- `category_id … PRIMARY KEY` : identifiant unique et non nul. La génération **automatique** du numéro s’écrit différemment : `GENERATED BY DEFAULT AS IDENTITY` (PostgreSQL), `AUTO_INCREMENT` (MySQL), `AUTOINCREMENT` après `INTEGER PRIMARY KEY` (SQLite).
- `VARCHAR(60) NOT NULL UNIQUE` : texte de 60 caractères au plus, obligatoire, sans doublon.
- `description VARCHAR(200)` : sans `NOT NULL`, la colonne **accepte NULL**.
- `ENGINE=InnoDB` (MySQL) : choisit le moteur de stockage qui gère les clés étrangères.

## Les contraintes, une par une

| Contrainte | Rôle | Exemple de la librairie |
|---|---|---|
| `PRIMARY KEY` | Identifie chaque ligne | `book_id` |
| `NOT NULL` | Interdit l’absence de valeur | `customers.email` |
| `UNIQUE` | Interdit les doublons | `books.isbn`, `payments.order_id` |
| `CHECK (condition)` | Impose une condition | `unit_price >= 0`, `quantity > 0` |
| `DEFAULT valeur` | Valeur si rien n’est fourni | `status` vaut `pending`, `country` vaut `France` |
| `FOREIGN KEY … REFERENCES` | Impose l’existence du parent | `orders.customer_id` |

### Clés étrangères et règles de suppression

Voici la table `orders` en PostgreSQL ; les deux autres moteurs écrivent la clé étrangère comme dernière ligne `FOREIGN KEY (customer_id) REFERENCES customers (customer_id) …` (voir `sql/mysql/02_schema.sql` et `sql/sqlite/02_schema.sql`).

```sql
CREATE TABLE orders (
    order_id     INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    customer_id  INTEGER     NOT NULL
                 REFERENCES customers (customer_id) ON UPDATE CASCADE ON DELETE RESTRICT,
    order_date   DATE        NOT NULL,
    status       VARCHAR(10) NOT NULL DEFAULT 'pending'
                 CHECK (status IN ('pending','paid','shipped','cancelled')),
    shipped_date DATE,
    CHECK (shipped_date IS NULL OR shipped_date >= order_date)
);
```

`ON DELETE RESTRICT` interdit de supprimer un client qui a des commandes. `ON DELETE CASCADE` (utilisé de `order_items` vers `orders`) supprime automatiquement les lignes dépendantes. `ON UPDATE CASCADE` répercute un changement de clé primaire. Le dernier `CHECK` mélange deux colonnes : une expédition ne peut pas précéder la commande, et `NULL` est autorisé tant que la commande n’est pas expédiée.

:::warning SQLite et les clés étrangères
SQLite **ignore les clés étrangères par défaut**. Il faut exécuter `PRAGMA foreign_keys = ON;` à **chaque nouvelle connexion**. Sans cela, il accepterait des commandes pour des clients inexistants. Tous les scripts du cours commencent par cette ligne.
:::

## L’ordre de création compte

Une clé étrangère ne peut référencer qu’une table qui **existe déjà**. On crée donc les tables **parents avant les enfants** :

1. `categories` et `customers` (aucune dépendance) ;
2. `books` (dépend de `categories`) ;
3. `orders` (dépend de `customers`) ;
4. `order_items` (dépend de `orders` et `books`) et `payments` (dépend de `orders`).

La suppression se fait dans l’ordre **inverse**. Le fichier `02_schema.sql` de chaque moteur respecte cet ordre.

## Comparer les types

| Notion | PostgreSQL | MySQL | SQLite |
|---|---|---|---|
| Identifiant auto | `GENERATED BY DEFAULT AS IDENTITY` | `AUTO_INCREMENT` | `INTEGER PRIMARY KEY AUTOINCREMENT` |
| Montant | `NUMERIC(8,2)` | `DECIMAL(8,2)` | `NUMERIC(8,2)` (affinité, voir chapitre 1) |
| Booléen | `BOOLEAN` (vrai type) | `BOOLEAN` = `TINYINT(1)` | `BOOLEAN` = entier 0/1 |
| Date | `DATE` | `DATE` | `DATE` (texte ISO `AAAA-MM-JJ`) |
| `CHECK` appliqué | Toujours | Depuis 8.0.16 | Toujours |

## ALTER TABLE : modifier une table existante

`ALTER TABLE` change la **structure** d’une table sans la recréer. Ajoutons une colonne `language` (NULL autorisé) au catalogue :

```sql run
ALTER TABLE books ADD COLUMN language VARCHAR(30);
SELECT book_id, title, language FROM books WHERE book_id <= 2 ORDER BY book_id;
```

Les lignes existantes reçoivent NULL pour la nouvelle colonne. Cette syntaxe d’ajout est identique sur les trois moteurs ; ce sont les modifications plus lourdes (changer un type, supprimer une contrainte) qui divergent. *Cet exemple modifie une copie : la base de référence n’est pas touchée.*

## DROP TABLE : supprimer une table

`DROP TABLE` supprime la table **et toutes ses données**, sans confirmation. Le moteur protège toutefois les tables référencées :

```sql error
DROP TABLE categories;
```

Les trois moteurs refusent, chacun avec son message : PostgreSQL *cannot drop table categories because other objects depend on it*, MySQL *Cannot drop table 'categories' referenced by a foreign key constraint*. Pour supprimer, il faut d’abord supprimer les tables enfants, ou utiliser `DROP TABLE … CASCADE` sur PostgreSQL.

:::error Erreur fréquente
Exécuter `DROP TABLE` ou le script de réinitialisation sur la **mauvaise base**. Vérifiez toujours la connexion active avant toute instruction destructive.
:::

:::exercise Exercice guidé : traduire des règles en contraintes|Niveau 1 · guidé
Règle : « un livre coûte au moins 0 €, son stock ne peut pas être négatif, et son ISBN est unique ». Écrivez les trois définitions de colonnes.
---solution---
```sql
isbn           VARCHAR(17)  NOT NULL UNIQUE,
unit_price     NUMERIC(8,2) NOT NULL CHECK (unit_price >= 0),
stock_quantity INTEGER      NOT NULL DEFAULT 0 CHECK (stock_quantity >= 0)
```
`UNIQUE` empêche deux livres de partager l’ISBN ; chaque `CHECK` exprime une borne ; `DEFAULT 0` évite de saisir le stock d’un livre pas encore reçu. Aucune de ces règles n’a besoin du code applicatif : le moteur les fait respecter pour tous.
:::

:::exercise Exercice autonome : la table reviews|Niveau 2 · autonome
Écrivez (en PostgreSQL) la table `reviews` du chapitre 2 : un avis par client et par livre, note de 1 à 5, commentaire facultatif.
---solution---
```sql
CREATE TABLE reviews (
    review_id   INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    customer_id INTEGER NOT NULL REFERENCES customers (customer_id),
    book_id     INTEGER NOT NULL REFERENCES books (book_id),
    rating      INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 5),
    comment     VARCHAR(500),
    UNIQUE (customer_id, book_id)
);
```
Les deux FK sont `NOT NULL` (un avis a toujours un auteur et un livre) ; `UNIQUE (customer_id, book_id)` est une contrainte **sur deux colonnes** ; `comment` reste nullable. Les tables `customers` et `books` doivent exister avant.
:::

:::quiz Pourquoi crée-t-on books avant order_items ?
- [ ] Par ordre alphabétique :: L’ordre alphabétique n’a aucune importance pour le moteur.
- [x] Parce que order_items contient une clé étrangère vers books, qui doit déjà exister :: Un parent est toujours créé avant ses enfants.
- [ ] Parce que books est plus petite :: La taille est sans effet.
:::

:::quiz Que se passe-t-il avec ON DELETE RESTRICT sur orders.customer_id ?
- [ ] Les commandes d’un client supprimé sont supprimées aussi :: C’est le comportement de CASCADE, pas de RESTRICT.
- [x] La suppression d’un client qui a des commandes est refusée :: RESTRICT protège le parent tant que des enfants le référencent.
- [ ] Le client est supprimé et les commandes passent à NULL :: Ce serait SET NULL, et customer_id est NOT NULL.
:::
